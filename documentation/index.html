1. Installation

  1. Unzip the download. You'll get a freshfold/ folder.
  2. Open pages/index.html directly in a browser to preview — no server or build tools needed.
  3. To go live, upload the entire folder to your host (cPanel / Hostinger File Manager, Netlify drag-and-drop, Vercel, GitHub Pages, S3). Keep the folder structure intact — pages use relative paths like ../assets/css/style.css.
  4. Point your domain's root at the folder. The root index.html redirects to pages/index.html. If you'd rather serve pages from the root, move the HTML files up one level and change ../assets/ to assets/ (a single find & replace).

Production checklist

  • Swap style.css, dark-mode.css, rtl.css, main.js and dashboard.js for their .min versions.
  • Replace https://www.freshfold.example with your domain (page heads, sitemap.xml, robots.txt).
  • Add your Formspree / Mailchimp / Maps / payment keys (section 7).
  • Remove the "Demo: next status" button on track-order.html and the demo hint on login.html.

4. Colours & fonts

All colours, radii, shadows and spacing live in :root at the top of assets/css/style.css:

:root {
  --ff-primary: #1a64e0;   /* aqua — links, primary buttons */
  --ff-secondary: #0d2547; /* ink navy — footer, dark bands */
  --ff-accent: #1a64e0;    /* coral — main CTAs */
  --ff-sun: #cfe1ff;       /* highlight */
  --ff-success / --ff-warning / --ff-danger / --ff-info  /* order statuses */
  --ff-font-display: "Outfit", …;
  --ff-font-body: "Plus Jakarta Sans", …;
  --sp-1: 8px … --sp-12: 96px;   /* 8 px spacing scale */
}

Dark mode is a true-black theme (--ff-bg: #000000, surfaces #0a0a0a / #141414, borders #2a2a2a) defined in assets/css/dark-mode.css. Keep text on --ff-primary backgrounds at 4.5:1 contrast or better — check with WebAIM.

Changing fonts

  1. Pick fonts on Google Fonts and replace the fonts.googleapis.com link in each page's <head>.
  2. Update --ff-font-display and --ff-font-body.

5. Content & branding

  • Brand name: find & replace FreshFold. The logo is text + icon (.ff-logo); replace with an <img> if you have a logo file.
  • Contact details: phone +91 80 4567 8900 / tel:+918045678900, WhatsApp 918045678900, email hello@freshfold.example, address in the footer and JSON-LD.
  • Images: all photos are bundled locally in assets/images/ and cropped to their frame with object-fit: cover (16:10 for services, 3:2 for process/about). Each <img> has a data-fallback pointing at a bundled illustration in assets/images/, swapped in automatically if a photo fails to load.
    To use your own photos: replace the files in assets/images/ (same file names), or save new ones there and update each <img src> (keep width/height). Search the pages for assets/images/ to find every one.
  • Banner backgrounds: every banner (home heroes, page headers, CTA banners, coloured bands, app promo, login/register panels, 404 and coming-soon) carries its photo in an inline style: style="background-image:var(--ff-overlay),url('../assets/images/your-photo.jpg') !important". Set it directly like this (not through a CSS variable), so the relative path resolves from the page. Replace the path with your own photo. The tinted overlay that keeps text readable is set per banner in style.css section 20 (--ff-overlay), with dark-mode versions in dark-mode.css and mirrored gradients in rtl.css. Remove ff-has-bg from a banner to go back to a plain colour.
  • Currency: prices in HTML use ₹. Change them in the pages and set CONFIG.currency / CONFIG.locale in main.js.
  • Testimonials, FAQ, team: plain HTML — edit in place. FAQ answers are mirrored in the page's FAQPage JSON-LD; keep them in sync.

6. JavaScript configuration

Open assets/js/main.js and edit the CONFIG object:

const CONFIG = {
  currency: "₹", locale: "en-IN",
  serviceAreas: { "560102": "HSR Layout", … },   // pincode → area name
  formspreeEndpoint: "https://formspree.io/f/YOUR_FORM_ID",
  mailchimpEndpoint: "https://YOUR_ACCOUNT.us1.list-manage.com/…",
  expressSurcharge: 0.5, sameDaySurcharge: 1.0,
  timeSlots: [ { id: "07-09", label: "7–9 AM", start: 7 }, … ]
};

Dashboard demo data (orders, tracking steps, transactions, saved addresses) is at the top of assets/js/dashboard.js — replace it with fetch() calls to your API.

Validation

Any form with data-validate gets friendly inline errors using native HTML constraints (required, type, pattern, minlength). Custom messages:

<input required data-error-required="Please enter your name." data-error="Format message">
<input data-match="password" data-error-match="Passwords don't match yet.">

Submit behaviour is set with data-submit: formspree, netlify, mailchimp or redirect (with data-redirect="dashboard.html"). Add data-success="…" for the confirmation text.

7. Forms & integrations

FormspreeCreate a form at formspree.io, put the ID into the contact form action and CONFIG.formspreeEndpoint.
Netlify FormsThe contact form already has data-netlify="true", a honeypot and form-name. Set data-submit="netlify" and deploy to Netlify.
MailchimpCopy your embedded-form action URL into CONFIG.mailchimpEndpoint. Field name is EMAIL.
Google MapsOn contact.html, replace the .ff-map placeholder content with the <iframe> from Google Maps → Share → Embed a map.
Stripe / PayPal / Razorpaypayments.html buttons carry data-pay-provider; wire them in initPayments() in dashboard.js. Use Stripe Elements / hosted checkout — never post raw card numbers to your own server.
Booking calendarLinks with data-booking-calendar call initCalendarHook() in main.js — open Calendly, Cal.com or your own scheduler there.
Live chatReplace the demo in initChat() with Crisp, Intercom, Tawk.to or Freshchat.
ChartsChart.js loads only on dashboard.html; data is in initCharts().

While endpoints contain YOUR_ (or the page is opened via file://), forms simulate a successful submit so you can demo the template offline.

8. Dark mode & RTL

A tiny inline script in every <head> applies the saved theme and direction before the page paints, so there is no flash. Buttons with data-theme-toggle and data-dir-toggle switch them; choices are saved in localStorage (ff-theme, ff-dir). With no saved choice, the OS setting (prefers-color-scheme) is used.

To ship an RTL-first site, set <html dir="rtl" lang="ar">, swap the Bootstrap stylesheet for bootstrap.rtl.min.css, and add an Arabic-friendly font such as Cairo or Tajawal.

9. SEO & performance

  • Every page has a unique <title> (≤ 60 chars), meta description (150–160 chars), canonical URL, Open Graph tags and exactly one <h1>.
  • JSON-LD: DryCleaningOrLaundry (schema.org's type for laundry/dry-cleaning businesses) on home and contact; FAQPage on home, service details and pricing. Validate at Rich Results Test.
  • Dashboard and auth utility pages are noindex and disallowed in robots.txt.
  • Images: WebP + JPG fallback, srcset/sizes, lazy loading below the fold, explicit dimensions (no layout shift).
  • Fonts use display=swap with preconnect; scripts are deferred.
  • For best PageSpeed scores: use the .min files, serve via a CDN with compression, self-host fonts, and keep replacement photos under ~150 KB.

10. Accessibility

  • Skip link, landmarks (header, nav, main, footer), labelled sections and forms.
  • Visible focus ring (coral outline), 44 px minimum touch targets, keyboard-operable carousel, tabs, accordion, wizard and sidebar (Esc closes).
  • Errors are linked with aria-describedby and aria-invalid; status messages use aria-live.
  • Animations respect prefers-reduced-motion.
  • Decorative icons are aria-hidden; icon-only buttons have aria-label.
